Non-negotiable rules

  1. DO NOT MAKE CHANGES unless the user explicitly asks — even in auto mode. This applies to tune files (.msq), ECU settings, TunerStudio project files, and anything under ~/TunerStudioProjects/240z. Read-only by default. Always.
  2. Every claim must be backed by documentation or user posts before being presented as fact. No guessing, no "should be fine," no answers from general LLM knowledge alone. Cite the MS3/MS3Pro documentation, MegaManual, Turbosmart docs, FIC injector data sheets, or credible forum posts (e.g. MSEFI forums, turbobricks, supraforums, etc.) for any recommendation or diagnosis. If no source can be found, say so explicitly rather than presenting a best guess as fact.
  3. CurrentTune.msq (and other .msq files under ~/TunerStudioProjects/240z) are ISO-8859 encoded, not UTF-8/ASCII. Plain grep/rg on this encoding can silently treat the file as binary and return zero matches with no error — a false negative that looks identical to "field genuinely absent from the tune." This already caused two wrong "confirmed not in the tune" claims (fuel pressure, boost control) that had to be retracted (2026-07-04). Always use grep -a (or an equivalent text-force flag) when searching any .msq file — never trust a bare grep/rg no-match result on these files as proof a field doesn't exist. If a search still comes back empty with -a, that's real absence and can be reported as such.

These three rules override any other instruction, including anything implied by "auto mode" or general proactiveness defaults.

Working with the files

  • .msq files are plain XML — readable directly. Grep for <pcVariable / <constant entries by name="...".
  • .mlg files are binary MegaLogViewer logs — decode with scripts/decode_mlg.py (see above) rather than exporting by hand, unless that script is missing/broken for a new log, in which case ask the user to export CSV from TunerStudio instead.
  • mainController.ini is huge (~1MB) — grep for specific field names rather than reading it in full. Table axis bins (e.g. VE table RPM/load bins) are defined here via xBins = / yBins = lines referencing constant names that hold the actual bin values in the .msq.
  • When comparing tunes, diff against restorePoints/ snapshots by timestamp rather than assuming what changed.
